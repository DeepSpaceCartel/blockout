# Blockout v0.3.0 plan

Teacher, parent and student accounts; a Turborepo monorepo; polished prototype games. Read CLAUDE.md first and follow it.

## Git rules (hard)
- **Branch:** work only on `v0.3.0`. Never check out, merge into, rebase or push `main`.
- **Pending changes:** commit the pending working-tree changes first. Leave `Blockout.pdf` untracked.
- **Commits and pushes:** commit after every finished step with a clear message, and push to `origin v0.3.0` after each stage. If pushing fails for permission reasons, keep committing locally and note it in the log.
- **Tests:** keep `npm test` green at every commit.
  - Add unit tests for every new rule.
  - Add a Playwright check (scratchpad scripts, per CLAUDE.md) for every new screen, and look at the screenshots.
- **Log:** keep `docs/v0.3.0-log.md` up to date: what's done, decisions made on the user's behalf, open questions, and how to try each feature. Where something is unclear, pick the sensible default, log it, and keep going. Never stop to ask.

## Stage 1: accounts, on today's layout (zero dependencies, `node:sqlite`)

### Auth
- **One module, four roles:** a single swappable auth module (client and server) with roles guest, student, teacher and parent.
- **No real registration.** For now a "dev login" picks or creates demo users.
- **Ready for Keycloak:** design it so Keycloak (OIDC, PKCE) drops in later. The server checks bearer tokens through one provider interface, and the dev provider issues HMAC-signed tokens.
- **Schools:** Keycloak will broker Google sign-in for students, restricted to `@iusd.org`. The first school is Cadence Park (IUSD, Irvine CA). Model a school with an allowed email domain.
- **Guest play always stays available, unchanged:** local progress, and join-by-code in live classes.

### Storage
- **sqlite** behind a small store module, holding:
  - users and schools
  - classes and class members
  - progress
  - assignments
  - parent links
  - scheduled tournaments
- **Progress sync:** signed-in students' progress syncs to the server. On first sign-in, the device's local progress merges into the account; after that the server copy wins, with local as a cache.

### Teacher
- **Hosting:** hosting a class requires a teacher account (gate at `openHostSetup()`).
- **Classes:** teachers create classes with a class code or link. Any `@iusd.org` student with the code joins the roster.
- **Class stats page:** each kid's Times Table mastery, facts that need practice, recent activity and homework status.
- **Scheduled tournaments:** class or school tournaments with a date and time, a format and a class. The lobby opens automatically at that time.

### Homework
- **Assignments** have a goal and a due date. Example goals:
  - master the ×7 table
  - finish N practice rounds on a difficulty
  - win on a board size

  Completion is detected automatically from progress events.
- **Who sets it:** the teacher sets class homework. Parents can also set extra homework for their own child.
- **Who sees it:** the student sees "📚 Homework" on the main menu. Teacher and parents see its status.

### Parent
- **Linking:** links to a child with a code from the child's account, or one given by the teacher.
- **What they can do:** see that child's stats and all their homework, and set extra homework.

### Privacy (kids under 13 in California: FERPA, COPPA, SOPIPA)
- **Names:** store first name + last initial only, and no Google email beyond an opaque subject ID.
- **Sharing:** no third-party sharing. Skip OpenAI name moderation for signed-in students.
- **Docs:** write a short `docs/privacy.md`.

### UI
Same style as the rest of the game: dialogs with a bottom button panel, kid-friendly wording, Chromebook and phone widths.

## Stage 2: Turborepo monorepo (make it very clean)
- **Tooling:** npm workspaces + Turborepo, Vite, plain JavaScript ES modules, no framework.
- **Layout:**

  | Path | What |
  |---|---|
  | `apps/multiplication` | the main game |
  | one app per prototype game | addition, subtraction, division, and the four fraction games |
  | `apps/server` | classroom + accounts + sqlite |
  | `packages/ui` | buttons, dialogs, tokens, icons, CSS |
  | `packages/engine` | board, dice, placement and CPU, with the operation passed in |
  | `packages/progress` | wallet, shop, achievements, facts, bonuses |
  | `packages/classroom` | classroom client |
  | `packages/auth` | auth module |

- **game.js:** split the 6000-line file into sensible modules.
- **Scripts and serving:** root scripts `dev`, `build`, `test` and `lint`. The server serves the built apps. The main game's More games button links to the other apps.
- **Docs:** update CLAUDE.md, the devcontainer script and README for the new layout.
- **Behaviour must be identical before and after.** Rerun every unit test and a full Playwright pass of the main flows: single player, practice, Home multiplayer, whole class, pairs, tournament, shop, wardrobe, cheats and accounts.

## Stage 3: polish the prototype games on the shared packages
